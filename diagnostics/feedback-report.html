Zero means the first rendered frame already contains the result. The harness issues shots just before rendering and measures pickups from rendered contact. Sound timing measures triggering the Web Audio cue, not physical speaker latency.

No duplicated shots, repeated pickup cues, or backward projectile frames occurred. Worst 95th-percentile projectile step error: 0.09 world units, below the 0.15-unit limit. Every pickup produced exactly one cue.

What changed. Local projectile presentation uses the shared trajectory rules. Action IDs join predictions to server confirmations; their clocks are aligned so confirmation does not rewind or accelerate a shot. Pickup visibility and inventory are predicted at local contact. The server checks every movement step and applies actions after their corresponding movement, allowing a newly collected missile to be fired immediately, even between rendered physics ticks.

Authority. The server still owns damage, kills, inventory and pickup ownership. Rejected or contested predictions revert. No client can submit a hit, inventory amount, pickup claim, or position. Duplicate actions do not create extra shots, and server cooldowns and movement credit still limit firing.

Regression checks. All 154 automated tests pass. Coverage includes delayed confirmation, ammo use, contested pickups, rejected shots, destruction, Vulcan cooldown resets, twelve Vulcan shots per second, duplicate requests, fast movement through pickups, and immediate use of a just-collected missile. The original four-profile browser movement matrix also passes, with position/camera error below its report precision.

Method. Real Chrome/WebGL, actual authenticated WebSockets and compression, and FIFO latency queues on both directions. Browser observations come from the same world view consumed by the renderer and HUD. This report covers the recorded scenarios; late server corrections can still reject a speculative shot or contested pickup.
