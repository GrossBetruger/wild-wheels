# Bomber photography

Bombers can take unlimited photographs without spending either type of bomb. PHOTO ∞ captures the game canvas after drawing, so it records the current 3D view, pan/zoom and 2D map selection. A brief flash and shutter sound confirm the shot. Capture uses a separate resized canvas to avoid reading a discarded WebGL buffer later.

After the match, every connected player automatically gets the shared album, including photos from multiple bombers. A server timestamp gives viewers a common four-second slideshow schedule. Previous/Next allow personal browsing; Close returns to the leaderboard and PHOTOS reopens the reel. Names and captions use text nodes. The normal sound toggle applies to shutter and slide sounds. Solo bomber play uses the same gallery locally.

Both servers keep image uploads separate from gameplay packets. Authenticated, active bombers can POST a JPEG to `/api/photos` with the current `X-Wild-Wheels-Epoch`. The API accepts at most two captures per player per simulated match second; there is no ammunition or photo-count allowance. Captures are resized to at most 800 × 500 and compressed to at most 64 KiB, with a server dimension ceiling of 960 × 600. Only bounded JPEG headers are inspected; the service does not decompress images on the simulation thread. Match duration and capture cadence bound storage. Albums are in memory, scoped to the current epoch and discarded when the next album request observes a new epoch. They do not survive a server restart.

Room members can GET `/api/photos` for the finished-match manifest and `/api/photos/{epoch}/{id}` for an image. Images are unavailable during play, to unauthenticated visitors or through an old match URL. Endpoints apply same-origin checks, bounded request bodies, image MIME types and no-sniff/no-store headers. Image bytes never enter WebSocket state packets.

Lightweight JS tests cover unlimited shots, per-match reset, invalid images, capture cadence and slideshow timing. Native Rust tests cover bomber/driver permissions, hidden in-progress albums, shared image retrieval after the finish and stale-epoch rejection. After pushing, `npm run test:photos` uses two isolated Chrome players, captures three nonblank 3D/map photos, checks no ammunition was spent, forces the Node test fixture to the finish, and verifies both players’ slideshow, sounds, slide changes and next-match cleanup. The fixture is local test code, with no production endpoint for ending matches.
